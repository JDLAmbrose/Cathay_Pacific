# 会员追踪看板 · 计划（v0.4）

> **v0.4**：会员看板收成香港—伦敦一条线。人群是学生、家长、商旅。书签六个。钻石行政卡只出现在返校，而且是 2027-01-01 之后新入会的商旅。
>
> **v0.3**：竖版。最上方是航线地图，数字是该航线正在使用 Plume Light 的会员数。家庭横向分流沿用货舱看板：左源、中分流、右状态卡。
>
> **v0.2**：看板不展示会员姓名或 `member_id`。演示看两件事：Plume Light 的潜力，以及它对国泰运营的帮助。数据包里的演示姓名只用于生成与核对，不进入界面。

对齐 [Member_Kanban_Requirements.md](Member_Kanban_Requirements.md) v0.4。本文只定界面、图和工程拆分。人数、比率、金额以种子 `20261111`、`schema_version` `2026-11-11.2` 的切片为准，界面持续标注「模拟数据」。

演示是一块竖版看板，从上往下读。拨动书签后，地图和下面各块一起变。地图独立放在最上方；漏斗和横向分流在各自的块里，不另开页面：

| 图 | 放在哪一块 | 看潜力 | 看对国泰运营的帮助 |
| --- | --- | --- | --- |
| 航线示意地图 | 顶栏之下，独立于 8 块 | 香港—伦敦这条线上现在有多少人在用 Plume Light | 学生、家长、商旅各多少 |
| 服务漏斗 | 第 3 块 | 了解服务之后有多少人付款 | 付费转化还剩哪一段空间 |
| 家庭横向分流 | 第 4 块 | 一名学生能连出多少家庭关系 | 授权和支付是两条线，关系卡在哪一段 |

其余五块用别的图：费用构成条、增量对照条、时间尺、等级并列柱、优惠码分列条。每块仍保留问题原文、主数字、分子和分母。

## 1. 口径锁定

计算与 `generate_member_snapshot.py` 的 `evaluate()` 一致。界面不重写公式。

| 项目 | 锁定 |
| --- | --- |
| 时钟 | `t_demo`，时区 `Asia/Hong_Kong`。默认书签 `P`：2026-11-10 09:30。不用电脑当前时间 |
| 书签 | 数据编号是 `A` `B` `C` `D` `P` `E`。条上不写字母，短名称：暑假前 6/17、行前 8/12、报到 9/16、回落 10/21、演示 11/10 09:30、返校 2027-01-13。报到的悬停只写留学生赴英报到。生成器可以保留货舱核对时刻，不放进看板书签 |
| 切片 | 入会、漏斗、邀请、支付、等级变更、周汇总都只取时间戳 ≤ `t_demo` 的记录 |
| 人群筛选 | 作用在第 2、3、5、6、7 块，共用同一批会员做分母。第 5 块再按周汇总的 `persona` 筛。第 1、4、8 块保持全量，并标明「未随人群筛选」 |
| 航线 | 地图和机票增量都只有 `HKG-LHR`。地图上的「使用中」按已支付订单把会员去重，卡片分三行：学生、家长、商旅。没有航线切换 |
| 空值 | 分母为 0 显示「无样本」，不用 0 的颜色去填图。分子为 0、分母大于 0 时显示 0 |
| 精度 | 比率四位小数，天数两位小数，金额到分。百分数可以展示，旁边保留分子和分母 |
| 成本 | 可变成本按收入 35% 占位，`cost_assumption_locked = false`。利润可显示并标明占位。优惠码 ROI 保持「未锁定」 |
| 隐私 | 界面不出现会员姓名、`member_id`、单个订单号或单个家庭。`display_name` 留在快照里，视图模型在交给组件之前丢掉。人群只到「学生 / 家长 / 商旅」 |

数据包里还有增长差、座位占比、临近出发告警、`CARGO` 书签。这四项不在 v0.2 的 8 个问题里，本演示不画。

## 3. 八块各用一张图

### 3.1 服务收入与贡献利润 — 横向构成条

主数字：已支付收入、贡献利润、平均每单利润、已支付订单数。

一条横向堆叠条，三段相加等于已支付 `revenue_hkd`：

| 段 | 字段 | 演示单价（旁注，不是现行官价） |
| --- | --- | --- |
| 取送 | `lanes.pickup_hkd` | HK$1,200 / 单 |
| 超额托运 | `lanes.extra_bag_hkd` | HK$600 / 件 |
| Cargo 行李 | `lanes.cargo_hkd` | HK$250 / 23 kg |

条下第二行用斜纹画出「收入的 35%」作为占位成本，实色段为贡献利润。斜纹上写：「可变成本按收入 35% 占位，尚未锁定」。未支付订单不进入这两条。

默认时钟 `P`：收入 **HK$283,400**，贡献利润 **HK$184,210**，**154** 单；平均每单收入 **HK$1,840.26**，平均每单利润 **HK$1,196.17**。

订单数和「已支付会员人数」在 `P` 恰好同为 154。图上仍分成两个数：第 1 块计订单，第 3 块计去重会员。

### 3.2 航线地图，然后才是入会数字

地图在第 2 块的数字之上，单独占竖版的第一屏。它回答的是「香港—伦敦这条线上现在有多少人在用 Plume Light」，不是已入会人数。

计数：已支付订单（`paid_at ≤ t_demo`）按航班航线把 `member_id` 去重。默认时钟 `P` 只有一条：

| 航线 | 使用中 | 其中 |
| --- | --- | --- |
| HKG–LHR | **154** | 学生 87，家长 42，商旅 25 |

154 与已支付会员人数一致。弧线从香港连到伦敦，粗细对应该人数。地图不切换航线，也不写「订单航线，不是居住地」。

地图用本地的世界轮廓，按经纬度标出香港和伦敦，不请求在线底图。人数写在航线卡片上，不压在国界上。人群筛选不改变这张图。

第 2 块本身留在地图下面，主数字仍是累计已入会、今日新增、本周新增、入会转化率。学生、家长、商旅三组始终分开。今日为 0 时显示 0。

地图下面、仍属于获取这一段的两件小图：

- **入会小漏斗**：`reach` → `start_join` → `complete_join`，宽度是去重人数。这张漏斗回答「能不能加入」，和第 3 块的服务漏斗分开。
- **累计曲线**：横轴是 6 个书签，纵轴是累计已入会。当前书签用竖线标出。拨钟时曲线的已走过部分变实、未到的书签变淡。`A` 到 `E` 的累计依次为 14、73、140、173、182、213。9 月 16 日只标「留学生赴英报到」。

默认 `P`：累计 **182**，今日 **0**，本周 **0**。入会转化率 **182 / 207 = 0.8792**，`start_join` **190**。学生 102，家长 52，商旅 28。全周期 214 不作为当前累计。

### 3.3 服务预订转化率 — 服务漏斗

主数字：已支付会员 ÷ 已入会会员。意向客（`join_at` 为空）不进分母。旁边并列「了解后付款」= `payment_success` 去重 ÷ `start_prepare` 去重。两个分母都写出来。比率旁注「含演示对齐」。这张漏斗看的是付费潜力还剩多少，不点进任何一位会员。

漏斗三层，宽度是到达该步且 `event_at ≤ t_demo` 的去重会员：

```text
了解服务   start_prepare      ████████████
到达结算   reach_checkout     ████████
支付成功   payment_success    ██████
```

层与层之间标流失人数。无样本时三层都是空框，不涂 0 的颜色。

默认 `P`：服务预订转化率 **0.8462（154 / 182）**。了解后付款 **154 / 157**。漏斗 157 → 155 → 154。

### 3.4 家庭互联率与成功率 — 横向分流

三个数都保留，不合成一个「家庭成功率」：

| 读数 | 公式 |
| --- | --- |
| 已发出 | `invited_at ≤ t_demo` 的关系数 |
| 互联率 | （已互联未授权 + 已授权）÷ 已发出 |
| 成功率 | 已授权 ÷ 已接受 |
| 已发出中的授权率 | 已授权 ÷ 已发出，单独标注，不画成第三条主带 |
| 学生带动 | 被邀请人是学生且已接受的关系数 ÷ 这些关系里的去重学生数 |

状态按需求 §4.1 的顺序判定：已取消 → 已拒绝 → 已撤销（曾接受则记为已互联未授权）→ 已授权 → 已互联未授权 → 待处理。支付不改变授权。

分流从左到右，带的粗细等于关系数。画法直接沿用货舱详情的横向分流，本图单独实现，不引用货舱的航班类型：

1. 左：一块实色源，写已发出和人数。
2. 中：半透明色带接到细的分流条，条旁写状态和人数。已接受最粗。
3. 右：白底状态卡，只从「已接受」分出。已授权用绿签，已互联未授权用金色签。卡上是人数和比率，没有姓名。

```text
已发出 ──┬── 已接受 ──┬── 已授权
         │           └── 已互联未授权
         ├── 待处理
         ├── 已拒绝
         ├── 已取消
         └── 已撤销
```

带上直接写人数。互联率标在「已发出 → 已接受」，成功率标在「已接受 → 已授权」。学生带动用一个平均数表达「一名学生对应多少条已接受的家庭关系」，旁边是分子和分母，没有姓名。

图下用三个人数说明支付和授权是两条运营线。只计数，不列出是谁：

| 计数 | 条件 | 运营上说明什么 |
| --- | --- | --- |
| 已支付、尚未授权 | 关系为已互联未授权，且被邀请人已有 `paid_at ≤ t_demo` 的订单 | 行李服务已经成交，家庭授权还没跟上 |
| 已授权、尚未支付 | 关系为已授权，且被邀请人有订单，但没有 `paid_at ≤ t_demo` | 家庭关系已经建立，服务收入还没落地 |
| 待处理且未入会 | 关系为待处理，且被邀请人尚未入会 | 家庭网络里还有未转化的入会潜力 |

这三数来自全体可见关系，不从某四个演示姓名里挑出来展示。快照里的演示姓名只保证生成结果可核对。

默认 `P`：发出 **38**，互联率 **0.7632**，成功率 **0.6207**，已发出中的授权率 **0.4737**。状态机计数是已接受 **29**、已授权 **18**、已互联未授权 **11**。三类缺口是已支付未授权 **9**、已授权未支付 **2**、待处理未入会 **1**。实现时以状态机计数为准。

### 3.5 额外机票消费及增量收入 — 对照条

增量用周汇总的 `incremental_revenue_hkd`。已结束的周和「本周至今」分开累计。学生、家长、商旅分列，三列之和等于当前筛选下的增量合计。不再按航线切换。

```text
学生   ██████░░░░          已完成周（实色）+ 本周至今（斜纹）
家长   █████░░░░
商旅   ████████░░░░
```

条上不提供会员、订单、班次入口。文案停在观察：这条伦敦线上的演示增量；不能从某一笔行李订单推出某一张机票。单位注明演示缩放值。

默认 `P`：已完成周 **HK$65,300**，本周至今 **HK$3,900**。其中学生 21,400 + 1,400，家长 18,300 + 1,300，商旅 25,600 + 1,200。

### 3.6 入会至首次预订的时间 — 时间尺

对已入会且已有支付的会员，时长 = 最早 `paid_at − join_at`，单位天。分位下标 `round(p × (n − 1))`。主数字是中位数、P90、样本人数。

一条横轴从 0 天拉到不少于 P90。P50、P90 各一枚刻度。轴下用浅色直方图表示样本落在哪些天，直方图不替代刻度。文案写「入会之后多久发生第一笔支付」。数据包里服务准备发生在入会完成之后，这张卡展示速度。

无人支付时整条轴空着，写「无样本」。

默认 `P`：**P50 40.75 天，P90 85.67 天，154 人**。书签 `A` 为无样本，第 3 块转化率为 0。

### 3.7 会员等级分布及使用率 — 并列柱

每个当前等级一根柱：柱高是人数，柱内填色比例是使用率（该等级中已有支付的人数 ÷ 该等级人数）。未入会会员不进这张图。

2027-01-01 00:00 HKT 之前只有 Green、Silver、Gold、Diamond 四根柱。该时刻起，新入会且入会等级就是 Diamond Exec 的商旅单独加一根柱，界面写「鑽石行政卡」。此前不为它留一根 0 柱，也不把既有 Diamond 升级进来。Diamond Plus 不出现。

默认 `P`：Green **92**（使用率 0.9457）、Silver **44**（0.7500）、Gold **32**（0.7500）、Diamond **14**（0.7143）。没有 Diamond Exec。书签 `E` 出现 Diamond Exec **8** 人，使用率 **0.6250**。

### 3.8 家庭优惠码使用率及 ROI — 分列条

使用率 = 带 `promo_code` 的已支付订单 ÷ 已支付订单。

两条横条：

| 条 | 内容 | 可展开 |
| --- | --- | --- |
| 拟议家庭码 | 订单数 + 收入，政策 `hackathon_proposed` | `PLUME-ENROL` / `PLUME-HOLIDAY` / `PLUME-GRAD` |
| 官方学生码 | 订单数，政策 `official_current` | `HKSTUDENT` |

`CXFAMILY` 不出现。

ROI 是一枚锁形标记，文字「未锁定」。不画仪表，不算比率。

默认 `P`：使用率 **0.3052**；家庭码 **24** 单，收入 **HK$39,350**；官方学生码 **23** 单。24 + 23 = 47，与 0.3052 × 154 单一致。商旅订单不带这两类码。

## 4. 讲解时图怎么动

讲解人只拨书签。四张图各自给出学期节奏，数字与 `kpi-at-bookmarks.json` 一致。

| 书签 | 地图 | 服务漏斗 | 家庭分流 | 其余 |
| --- | --- | --- | --- | --- |
| `A` 暑假前 | 伦敦弧上使用中为 0，累计 14 | 支付层为 0，转化率 0 | 邀请尚未发出 | 第 6 块无样本 |
| `C` 留学生赴英报到 | 伦敦弧上使用中 49 | 漏斗三层都在 | 分流带随邀请变宽，仍只有人数 | 累计 140 |
| `P` 产品演示时钟 | 使用中 154，学生 87、家长 42、商旅 25。累计 182，今日 0、本周 0 | 154 / 182，旁注含演示对齐 | 38 → 29 → 18，三类缺口 9 / 2 / 1 | 第 5 块本周至今 HK$3,900。没有钻石行政卡 |
| `E` 一月返校 | 使用中 180。累计 213 | 随切片变宽 | 随切片重计 | 第 7 块多出钻石行政卡 8 人，使用率 0.6250 |

拨钟时 8 块同一次重算。色带宽度、漏斗宽度、弧线粗细用 400ms 过渡；系统开启「减少动态效果」时直接跳到新宽度。

## 5. 技术架构

放在现有 `kanban-app`（React 19 + Vite + TypeScript）里，作为第二块看板。顶栏增加「貨艙 / 會員」。货舱页的时钟、引擎和快照保持原样。两边共用色板、`useI18n()` 和「僅限國泰員工」顶栏。

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 图 | 受控 SVG | 漏斗层数、分流断带、无样本空框、ROI 锁都要按口径画。色带算法与货舱分流图同一路数，组件和类型分开 |
| 地图 | 本地世界轮廓 SVG，经纬度定位 | 画出香港到伦敦。不请求在线底图 |
| 数据 | 只读冻结 JSON | `member-snapshot.json`、`kpi-at-bookmarks.json` 拷入 `kanban-app/public/data/`。快照不进旅客页，不写旅客 `localStorage` |
| 计算 | 纯函数 `evaluateMembers(snapshot, tDemo, filter)` | 拨钟和筛选都是一次函数调用。组件只渲染返回值 |
| 请求 | 沿用现有的本地 JSON 读取 | 组件通过一个 hook 拿视图模型。以后若接 API，换这个 hook 的数据源 |

改口径时先改 `generate_member_snapshot.py` 和核对文件，再重新拷贝 JSON。前端不生成会员。
