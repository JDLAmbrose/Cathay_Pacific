## 1. 目的

**看板让国泰员工在同一个演示时钟下看完这 8 件事。** 看的是 Plume Light 的潜力，以及对国泰运营的帮助：服务收入、会员获取、付费转化、家庭关系、机票增量、入会后的消费速度。界面只到人群和这一条航线，不展示会员姓名。

| # | 展示 | 要回答的问题 | 主数字 |
| --- | --- | --- | --- |
| 1 | 服务收入与贡献利润 | Plume Light 能赚多少钱？每单利润多少？ | 已支付收入、贡献利润、平均每单利润 |
| 2 | 新会员获取及入会转化率 | 服务能否吸引学生或家长加入国泰？ | 新增与累计，学生 / 家长 / 商旅分开；`complete_join ÷ reach` |
| 3 | 服务预订转化率 | 有多少人了解服务后真正付款购买？ | 已支付会员 ÷ 已入会会员；服务漏斗直到支付成功 |
| 4 | 家庭互联率与成功率 | 能否通过一名学生建立更多家庭会员关系？ | 接受率、授权率、每名学生对应的已接受家庭关系 |
| 5 | 额外机票消费及增量收入 | 家长是否因探望学生而增加机票消费？ | 学生、家长、商旅分列的周增量 |
| 6 | 入会至首次预订的时间 | 新会员是否很快开始消费？ | 首次支付距入会的中位数与 P90 |
| 7 | 会员等级分布及使用率 | Green、Silver、Gold 等会员中，哪些更愿意购买？ | 各等级人数，以及该等级中已支付的比例 |
| 8 | 家庭优惠码使用率及 ROI | 家长机票优惠能否带来足够收益？ | 家庭码与官方学生码分列；ROI 在成本锁定前保持未锁定 |

8 块共用同一次切片：给定演示时钟 `t_demo`，只计入时间戳小于等于 `t_demo` 的入会、漏斗、邀请、支付和周汇总。拨动时钟后，8 块一起变。

### 1.1 业务背景

会员看板的试点人群是赴伦敦的学生、家长，以及同一条线上的少数商旅。Plume Light 提供出发前的行李服务：上门取送、超额托运、Cargo 行李。家庭可以互联并授权，支付和授权是两条线。家庭关系只配对家长和学生。商旅不进家庭关系。

看板用演示数据把「赚多少、谁加入、谁付款、家庭能否连上、家长机票有没有增量、多久发生第一单、哪一级更愿意买、优惠码是否划算」放在同一屏。

### 1.2 边界

1. 全部人数、转化率、收入都是种子 `20261111` 的演示模拟。界面持续标注「模拟数据」。
2. 合成会员没有票号、护照。机票增量只有「周 × 人群 × 航线」，航线只有 `HKG-LHR`。数据包里可为生成与核对保留 May、Lin、Emily 的姓名；Alex 不进入会员快照。看板不展示任何会员姓名或 `member_id`。
3. 看板只展示，不发邀请、不改等级、不催付、不退款。
4. 支付成功不自动变成家庭已授权。
5. 可变成本按收入的 35% 占位，`cost_assumption_locked = false`。贡献利润可以显示，并标明占位。优惠码 ROI 保持未锁定，不写成结论。
6. 页面标注「僅限國泰員工 · 營運演示」。这是界面用途，不是登录鉴权。
7. 数字来自冻结快照。拨动 `t_demo` 即重新切片，不使用电脑当前时间。

## 4. 口径

| 术语 | 定义 |
| --- | --- |
| `t_demo` | 演示时钟。8 块数字都相对这一时刻 |
| 已入会 | `join_at` 有值且 `join_at <= t_demo` |
| 意向客 | `join_at` 为空。可以已有 `reach` 或 `start_join`。数据包里有未入会的演示关系属于这一类 |
| 触达 / 开始入会 / 完成入会 | `reach`、`start_join`、`complete_join`，且 `event_at <= t_demo`。`complete_join` 的时间等于 `join_at` |
| 了解服务 | 已有 `start_prepare`，且 `event_at <= t_demo` |
| 服务使用者 | 至少一笔订单 `paid_at <= t_demo` |
| 当前会籍 | `t_demo` 之前最后一次有效等级变更，否则为入会等级。未入会没有等级。`Diamond Exec` 在 2027-01-01 00:00 HKT 之前不生效 |
| 本周 | `t_demo` 所在周的周一 00:00 HKT 至 `t_demo`。未结束的周标「本周至今」 |
| 今日 | `t_demo` 的本地日历日 |
| 贡献利润 | 收入 − 假设可变成本。成本比率 35%，尚未锁定 |
| 家庭码 | `PLUME-ENROL`、`PLUME-HOLIDAY`、`PLUME-GRAD`，政策标记 `hackathon_proposed` |
| 官方学生码 | `HKSTUDENT`，政策标记 `official_current`。目录里没有 `GBASTU` |

切片规则：

1. 漏斗、邀请、支付、等级变更、周汇总都按 `t_demo` 切。
2. 文件里的「已入会 214」是全周期人数，含演示人物 May、Lin。默认时钟下的累计会员是 **182**。界面展示切片结果。2027-01-13 09:30 的累计是 213，因为有一人在该时刻之后才入会。
3. 分母为 0 时显示「无样本」。分母大于 0、分子为 0 时显示 0。
4. 学生高峰在 8 月 12 日、9 月 10 日、1 月 8 日。家长高峰在 8 月 20 日、9 月 8 日。商旅全年平缓。9 月 16 日的书签只写留学生赴英报到。

### 4.1 家庭关系状态

只看 `invited_at <= t_demo` 的关系。判定顺序：

| 顺序 | 条件 | 状态 |
| --- | --- | --- |
| 1 | `cancelled_at <= t_demo` | 已取消 |
| 2 | `declined_at <= t_demo` | 已拒绝 |
| 3 | `revoked_at <= t_demo`，且此前已接受 | 已互联未授权 |
| 4 | `revoked_at <= t_demo`，且从未接受 | 已撤销 |
| 5 | `authorized_at <= t_demo` | 已授权 |
| 6 | `accepted_at <= t_demo` | 已互联未授权 |
| 7 | 仅已发出邀请 | 待处理 |

已接受 = 已互联未授权 + 已授权。已授权只计第 5 步。

### 4.2 演示关系（默认时钟，不展示姓名）

数据包保留 May–Lin（已支付、未授权）、May–Emily（邀请待处理、未入会），以及伦敦线上另一对「已授权、学生尚未支付」。Alex 不进入会员快照。看板不渲染任何会员的姓名或 `member_id`。第 4 块用三类匿名计数表达同一件事：已支付仍未授权、已授权尚未支付、邀请待处理且未入会。

### 4.3 服务价格（演示参数）

已支付订单才进入第 1、3、7、8 块。单价来自产品 README，界面注明不是现行官价。

| 组成 | 演示价 |
| --- | --- |
| 取送 | 每单 HK$1,200 |
| 超额托运 | 每件 HK$600 |
| Cargo 行李 | 每 23 kg 计费单位 HK$250 |

未支付订单收入为 0，不进入第 1 块，也不进入「已使用服务」。

`CXFAMILY` 不发放。看板不出现它。学生可以用 `HKSTUDENT`，家长可以用家庭码，商旅两者都不用。

## 6. 指标规格

公式与 `generate_member_snapshot.py` 的 `evaluate()` 一致。比率保留四位小数，时长保留两位小数，金额保留到分。界面可以用百分数展示，核对时以该精度为准。

| 块 | 指标 | 公式 |
| --- | --- | --- |
| 1 | 服务收入 | 已支付订单 `revenue_hkd` 之和 |
| 1 | 贡献利润 | 已支付订单 `contribution_profit_hkd` 之和 |
| 1 | 平均每单收入 | 服务收入 ÷ 已支付订单数 |
| 1 | 平均每单利润 | 贡献利润 ÷ 已支付订单数 |
| 2 | 累计 / 今日 / 本周 | `join_at <= t_demo`；其中今日从本地日 00:00 起，本周从周一 00:00 起 |
| 2 | 入会转化率 | `complete_join` 去重 ÷ `reach` 去重 |
| 2 | 开始入会率 | `start_join` 去重 ÷ `reach` 去重 |
| 3 | 服务预订转化率 | 有支付的会员人数 ÷ 已入会人数 |
| 3 | 了解后付款 | `payment_success` 去重 ÷ `start_prepare` 去重 |
| 4 | 互联率 | （已互联未授权 + 已授权）÷ 已发出 |
| 4 | 成功率 | 已授权 ÷ （已互联未授权 + 已授权） |
| 4 | 已发出中的授权率 | 已授权 ÷ 已发出。单独标注 |
| 4 | 学生带动 | 被邀请人为学生且状态属于已接受的关系数 ÷ 这些关系中的去重学生数 |
| 5 | 机票增量 | 可见周的 `incremental_revenue_hkd`。周末 ≤ `t_demo` 的周为已完成；当周为「本周至今」 |
| 6 | 入会至首次预订 | 最早 `paid_at − join_at`（天）的 P50 与 P90。分位下标为 `round(p × (n − 1))` |
| 7 | 等级人数 | 已入会会员的当前等级计数 |
| 7 | 等级使用率 | 该等级中有支付的人数 ÷ 该等级人数 |
| 8 | 优惠码使用率 | 带 `promo_code` 的已支付订单 ÷ 已支付订单 |
| 8 | 家庭码 / 学生码 | `promo_family = proposed_family` 与 `official_hkstudent` 分开。没有 `official_gbastu` |
| 8 | ROI | 成本未锁定时为空 |

第 5 块不从服务订单推导。

### 6.1 默认时钟验收数字

书签 `P` · 2026-11-10 09:30，来自 `kpi-at-bookmarks.json`。

## 7. 可视化

8 块在同一看板里按第 1 节的顺序排列。每块都有：问题原文、主数字、分母或对照、模拟数据标记。具体版式在计划文档里定。

| 块 | 必须能一眼读到 |

| 4 | 发出、互联率、成功率；学生带动；支付与授权两条线的匿名计数。无会员姓名 |

| 6 | 中位数、P90、样本人数 |
| 7 | 已生效等级的人数与使用率并列。返校之前是四档，返校多出钻石行政卡 |
| 8 | 家庭码与官方学生码分列；ROI 为「未锁定」 |
| 控制条 | 当前 `t_demo`、书签、人群筛选、模拟数据标记 |

颜色沿用员工端色板：深绿顶栏、纸色底。无样本不用 0 的颜色去填充。

## 8. 数据需求

### 8.1 来源

| 数据 | 状态 |
| --- | --- |
| `member-snapshot.json` | 已生成。看板只读这份快照，或读与它同构的文件 |
| `kpi-at-bookmarks.json` | 书签核对值 |
| `generate_member_snapshot.py` | 种子 `20261111` 可重复生成。改口径时先改脚本和核对文件 |

快照 `meta.data_class = simulated`。界面展示该标记。

### 8.2 实体

| 实体 | 这 8 块用到的字段 |
| --- | --- |
| `members` | `member_id`、`display_name`、`persona`、`corridor`、`origin_region`、`join_at`、`tier_at_join`、`tier_changes[]`、`is_demo_persona` |
| `funnel_events` | `member_id`、`event_at`、`event_type` |
| `family_links` | `inviter_id`、`invitee_id`、`relationship`、`method`、六个时间戳 |
| `service_orders` | `member_id`、`paid_at`、`lanes`、`revenue_hkd`、`contribution_profit_hkd`、`cost_assumption_locked`、`promo_code`、`promo_family`、`occasion` |
| `ticket_increment_weekly` | `week_start`、`corridor`、`persona`、三列销售额。没有人的主键 |
| `promo_catalog` | `code`、`family`、`occasion`、`policy` |

订单上的 `schedule_instance_key` 保留在数据里，供收入与会员对齐。界面的 8 块不展开班次运行信息。

### 8.3 规模（全文件，未切片）

| 对象 | 数量 |
| --- | --- |
| 已入会（`join_at` 有值） | 214。配额学生 120、家长 56、商旅 36，另加已入会的演示人物 May、Lin |
| 意向客 | 32，含 Emily |

### 8.4 展示限制

合成会员在数据里以 `member_id` 标识。看板不展示 `member_id` 或姓名。第 5 块停在周和人群，航线只有伦敦。演示人物的姓名只留在数据包，供 §4.2 的核对，不进入界面。
