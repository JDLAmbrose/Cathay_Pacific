## 1. 目的与一句话定义

**看板帮助国泰员工回答三个问题：**

| 编号 | 问题 | 性质 | 时间范围 |
| --- | --- | --- | --- |
| **Q1** | 目前任意航班的载重压力有多大？ | 监控 | 任意时刻 |
| **Q2** | 某一航班有超重风险时，能否把 Plume Light 的 Cargo 行李挪到更晚的航班，来缓解或避免？ | 规划 | 起飞前约 2 天内（窗口为参数） |
| **Q3** | 登机前，当前航班的行李总量是否已经超标？目前货舱状态如何？ | 临近起飞的预警 | 起飞前数小时（阈值为参数） |

三个问题共用同一个计算引擎：**「压力与缺口」→「缓解可行性」**，区别只在输入的新鲜度和约束强度。

### 1.1 业务背景

国泰员工通过看板获得行李预报，辅助装载规划，减轻行李压力，并为商货留出更确定的规划余量。价值路径是：

```text
更准的行李预报 → 更小且有依据的安全缓冲 → 更确定的可用余量 → 避免超重、减少临时处理
```

### 1.2 非目标

1. **不自动改配载。** 看板是规划与预警参考，最终配载仍由航司流程确认。
2. **不宣称增加飞机的物理容量。** 只提高规划确定性与调度灵活性。
3. **不做调度执行。** 没有调度指令、工单、通知、审批和审计。
4. **不调度商业货物，也不涉及货机（747-8F 等）。** 商货只作为固定输入。
5. **不处理单个旅客的超重行李。** 「超标」只指整班总量超过货舱规划预算。
6. **不做员工登录与鉴权。** 与 README 的现状一致，页面仅标注"僅限國泰員工"。

## 3. 范围

### 3.1 范围内

| 项目 | 说明 |
| --- | --- |
| 航线 | 同一机场对：出发 HKG，到达同一机场（演示为 LHR） |
| 航班 | 主要为国泰客机，机型为 A350-900、A350-1000、777-300ER |
| 货舱 | 客机下层货舱（腹舱）的重量与体积 |
| 可调度对象 | **仅 Plume Light 中选择「由 Cathay Cargo 调度」的托运行李** |
| 调度方向 | **只往后挪**：转到同一机场、起飞更晚的航班 |
| 调度窗口 | 默认 **2 天**，可配置（可用 2–3 天） |

### 3.2 固定负载与可调负载

这是理解全部指标的关键，必须在界面和数据中区分。

| 负载 | 是否可调 | 说明 |
| --- | --- | --- |
| 旅客随机托运行李（含 Plume 中选「随本趟航班」的行李） | 否 | 行李必须与旅客同班，属固定负载 |
| 未申报旅客的基线补估行李 | 否 | 系统估算，固定负载 |
| 其他货物（商货等） | 否 | 本期作为输入值，不调度 |
| 缓冲 | 否 | 营运输入 |
| **Plume Cargo 调度行李** | **是** | 这是唯一的可调负载 |

## 4. 核心概念与口径

| 术语 | 定义 |
| --- | --- |
| 货舱预算 | 分配给「旅客行李 + Plume Cargo 行李」的规划重量与体积，由营运输入，默认值可由机型容量推导（见 §8.2）。**不是飞机 MTOW，也不是整个货舱** |
| 可用量 `W_avail` | 预算 − 其他货物 − 缓冲 |
| 负载 `W_load` | 旅客行李（已申报 + 补估，或实测）+ 本班的 Plume Cargo 行李 |
| 余量 `Margin` | `W_avail − W_load`（体积同理） |
| 利用率 `U` | `W_load / W_avail`，即负载占**可用量**的比例（重量 `U_w`，体积 `U_v`）。分母是扣除其他货物与缓冲之后的可用量，这样 `U ≥ 1` 与 `Margin ≤ 0` 等价，两个口径不会互相矛盾 |
| 压力指数 CSI | `max(U_w, U_v)`；较大的一方为瓶颈 `bottleneck = weight \| volume` |
| P90 负载 | 带不确定性的保守负载值，见 §6.2 |
| 缺口 `Deficit` | `max(0, P90 负载 − 可用量)`，重量与体积分别计算 |
| 可调量 | 本班上状态允许移动、且有可行目标航班的 Plume Cargo 行李的总量 |
| 承接量 | 候选目标航班在安全垫之后还能接收的量 |
| 数据成熟度 | 覆盖率、补估占比，反映预报可信程度 |

**重要原则：**

1. 未申报旅客不得当作 0，必须用基线补估，并标注数据来源。
2. 同一件行李只计一次（`itemId` 唯一）。
3. 重量与体积是双约束，缺尺寸时体积显示「待补充」，不输出假精确的余量。
4. 所有结论都是「规划参考」，文案不得写成"已批准"或"确定可售"。

## 6. 指标与规则规格

### 6.1 指标清单

| 指标 | 公式或定义 | 用于 | 优先级 |
| --- | --- | --- | --- |
| 申报覆盖率 | `ΣDeclared / ΣPAX`，多航班按加权汇总，禁止对各班覆盖率取算术平均 | Q1 | P0 |
| 重量／体积利用率 | `W_load / W_avail`；`V_load / V_avail`（分母为可用量） | Q1, Q3 | P0 |
| CSI 与瓶颈 | `max(U_w, U_v)`；`bottleneck` | Q1, Q3 | P0 |
| 重量／体积余量 | `W_avail − W_load` | Q1, Q3 | P0 |
| 不确定性占比 | `W_imputed / W_predicted` | Q1 | P0 |
| P90 负载与超限概率 | 见 §6.2 | Q1, Q3 | P0 |
| 缺口 | `max(0, P90 − 可用量)` | Q2 | P0 |
| 可调量、承接量、缓解结论 | 见 §6.4 | Q2 | P0 |
| 实测偏差 | `(实测 − 预报) / 预报` | Q3 | P0 |
| 处理进度 | 各状态件数 / 总件数 | Q3 | P0 |
| 风险等级 | 规则见 §6.5 | Q1, Q3 | P0 |
| 窗口总余量、负载不均衡度 | 窗口内各班 P90 余量之和；各班利用率的标准差 | Q2 | P1 |
| 调度弹性 | 每件可调行李的可选目标航班数 | Q2 | P1 |

### 6.2 不确定性与 P90

预计总重 = 已知重量 + 补估重量。补估来自基线，是主要误差来源，所以必须提供区间。

```text
W_point = W_known × (1 + b) + n_undeclared × w_baseline
σ_total = σ_p × √n_undeclared
W_P90   = W_point + 1.2816 × σ_total
P(超限) = 1 − Φ((W_avail − W_point) / σ_total)
```

| 参数 | 默认值 | 来源与性质 |
| --- | --- | --- |
| `w_baseline` | 31.0 kg/人 | 来源 [Aircraft Commerce 假设](../doc/Aircraft_Capacity_Reference.md#3-规划推导参数项目假设)，演示原值 30 kg |
| `σ_p`（人均重量标准差） | 12 kg | **演示假设，无引用，需校准** |
| `b`（自报重量偏差系数） | 5% | **演示假设，无引用，需用实测校准** |
| 体积基线 | 待定 | 演示为 0.15 m³/人；参考值为 0.272 m³/人，口径待确认 |

体积的 P90 用同样的结构，缺尺寸时输出「待补充」，不输出区间。

### 6.3 状态机：Plume Cargo 行李

```text
已申报 → 已入库 → 已装箱 → 已装机 → 已交接目的地
              ▲
              └── 仅此状态允许调度
```

| 状态 | 含义 | 是否可调 |
| --- | --- | --- |
| 已申报 | 旅客已保存预报，行李尚未交给航司 | 是（只是计划，尚无实物） |
| 已入库 | 行李已到达航司仓库 | **是** |
| 已装箱 | 已装入集装器 | 否 |
| 已装机 | 已装上飞机 | 否 |

> 「已装箱」是本文新增的状态，README 现有的交接事件只有"到达机场、装机、当地物流接收"。

### 6.4 缓解可行性算法

```text
对有缺口的航班 F：
  M = F 上 状态 ∈ {已申报, 已入库} 的 Plume Cargo 行李
  T = { 候选航班 t | 满足 §5.2 的全部航班级约束 }
  对每个 t ∈ T：
      承接量_t = max(0, 可用量_t − P90 负载_t − 安全垫)    # 重量、体积分别算
  对每件 m ∈ M：
      可选目标集 = { t ∈ T | t 到达时间 + 末程时长 ≤ m.最晚送达 }
  分配：按「对缺口贡献最大的约束维度」降序，逐件放入承接量最大的可选目标
  缓解能力 = 已成功分配的行李重量与体积之和

结论：
  缺口 = 0                                → 无需调度（可标记「预防性」，若 P(超限) 偏高）
  重量缺口与体积缺口都 ≤ 缓解能力        → 可缓解
  0 < 缓解能力 且 仍有残余缺口            → 部分缓解（显示残余缺口）
  缓解能力 = 0 或 T 为空                  → 无解
```

补充规则：

- 目标航班放入后，利用率超过「高风险」阈值则不得接收，避免转移问题。
- `安全垫` 是目标航班保留的余量比例，默认值为配置参数。
- 窗口内 `Σ 承接量 < 总缺口` 时，附加「窗口内整体偏紧」提示。

### 6.5 风险等级与告警默认规则

**以下阈值是演示默认值，必须由营运方确认后才可用于真实判断。**

| 等级 | 条件（任一满足） |
| --- | --- |
| 正常 | CSI < 0.85 且 P(超限) < 5% 且覆盖率 ≥ 80% |
| 注意 | 0.85 ≤ CSI < 1.0，或 5% ≤ P(超限) < 20%，或覆盖率 50–80%，或数据过期 |
| 高风险 | CSI ≥ 1.0，或 P(超限) ≥ 20%，或覆盖率 < 50%，或关键字段缺失，或航班已取消但行李未冻结 |

**Q3 临近起飞的告警（基于实测）：**

| 等级 | 条件 |
| --- | --- |
| 提示 | 预计最终值的 P90 利用率 ≥ 0.85 |
| 警告 | 预计最终值的 P90 利用率 ≥ 0.95，或实测偏差超过 ±10% |
| 紧急 | 实测累计已超预算，或预计最终值的 P90 利用率 ≥ 1.0 且未装机行李不足以补救 |

| A350-900 | 172 m³ | 42,500 kg | ≈ 22,050 kg |
| A350-1000 | 208 m³ | 52,500 kg | ≈ 26,660 kg |
| 777-300ER | 213.8 m³ | 待补 | ≈ 27,410 kg（仅体积口径） |

「规划重量上限 = min(分舱载重合计, 体积 × 128.2 kg/m³)」是项目假设。**这些是货舱物理容量，不是看板中的货舱预算。** 货舱预算由营运输入，演示可取其中一部分。

### 8.3 概念实体（供后端设计参考，不是接口定义）

| 实体 | 关键字段 |
| --- | --- |
| 航班实例 `FlightInstance` | `scheduleInstanceKey`、承运人、航班号、出发与到达机场、出发与到达时间（local/utc）、机型、`totalSeats`、状态、`updatedAt`、数据来源（OAG／种子） |
| 机型容量 `AircraftCapacity` | 机型码、LD3 数量、可用体积、分舱载重上限、规划重量上限、来源编号 |
| 航班载荷输入 `FlightLoadInput` | 航班键、预计 PAX、重量预算、体积预算、其他货物重量与体积、缓冲、基线参数 |
| 行李项 `BaggageItem` | `itemId`、订单号、航班键、重量、体积、运输方式（随机／Cargo）、状态、**入库时间**（新增）、**最晚送达时间**（新增）、实测重量、更新时间、版本 |
| 缓解结果 `ReliefResult`（派生，不落库） | 航班键、缺口、可调量、目标分配、残余缺口、结论 |
| 参数 `Config` | `windowDays`、`alertHours`、安全垫、风险阈值、`σ_p`、`b` |

### 8.4 演示模拟数据

| 项目 | 要求 |
| --- | --- |
| 航班 | 6–8 个同航线航班，覆盖 3 种机型，起飞时间跨 3–4 天 |
| 场景覆盖 | 至少各 1 个：正常、注意（重量瓶颈）、注意（体积瓶颈）、高风险、无申报数据 |
| Plume Cargo 行李 | 6–10 个订单，含不同状态与最晚送达，保证 Q2 能出现「可缓解」「部分缓解」「无解」三种结论 |
| 实测数据 | 1–2 个临近起飞航班带实测值，保证 Q3 能触发「警告」与「紧急」 |
| 标注 | 所有模拟数据在界面和数据文件中显式标注「模拟数据」；容量参数带来源编号 |

## 9. OAG 接入

### 9.1 已查证

| 项目 | 内容 |
| --- | --- |
| 端点示例 | `https://api.oag.com/flight-instances/`，来自 [OAG 开发者门户首页](https://developers.oag.com/) 的官方请求示例 |
| 示例参数 | `DepartureDateTime`、`ArrivalDateTime`、`DepartureAirport`、`ArrivalAirport`、`CodeType`、`version=v2` |
| 认证 | Header `Subscription-Key` |
| 免费额度 | 每月 1,000 次调用，每次最多 10 条结果，每 30 天重置 |
| 响应字段 | 见 [Response Layout](https://knowledge.oag.com/docs/flight-info-api-response-layout-descriptions)：`Carrier`、`flightNumber`、`departure`/`arrival`、`aircraftType`、`serviceType`、`restrictions`（含 `cargo`）、`freightClasses`、`totalSeats`、`state`、`updatedAt`、`scheduleInstanceKey` 等 |
| 额外内容参数 | `Status`、`Seats`、`ActualSeats`、`ExtendedSchedules`，可能产生额外费用 |
| 去重 | 联营航班可能重复出现，需用 `codeshare`／`operatingFlight` 去重，避免容量重复计算 |

### 9.2 OAG 不提供

货舱容量（kg、m³）、实际载客数、行李件数／重量／体积、货物预订。

### 9.3 待验证（拿到 key 后实测）

| 问题 | 影响 |
| --- | --- |
| `DepartureDateTime` 是单日还是日期范围？ | 决定 2 天窗口需要几次调用 |
| 是否有承运人过滤参数？ | 避免超过每次 10 条 |
| 超过 10 条如何分页？ | 能否一次取全窗口内航班 |
| 状态相关内容参数的实际写法 | 决定能否取到延误与取消 |
| 取消航班在结果中如何出现？ | 决定候选航班的剔除逻辑 |
| `aircraftType` 返回码是否与 `359`／`351`／`77W` 一致？ | 决定机型容量表的键 |

### 9.4 接入原则

1. **key 不得出现在前端代码或发布包中。** 前端没有后端，推荐用预取脚本把结果写成静态 JSON，前端只读该文件。
2. **种子数据始终保留作为兜底。** 没有 key 或调用失败时，看板用种子数据，且界面标注数据来源。
3. 航班状态变化（取消、延误）可通过轮询或后续接入 OAG Flight Info Alerts 获得，本期不要求实时推送。

## 11. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-K1 | 打开看板 | 看到不少于 6 个航班，按风险排序，至少出现「正常」「注意」「高风险」各一 |
| AC-K2 | 展开一班 | 看到瀑布图，补估部分有区间；无申报数据的航班有明确标注 |
| AC-K3 | 缺尺寸 | 体积显示「待补充」，不输出假精确余量 |
| AC-K4 | 有缺口的航班 | 缓解面板显示缺口、可调行李、候选航班、结论与残余缺口 |
| AC-K5 | 三种结论 | 演示数据中能分别看到「可缓解」「部分缓解」「无解」 |
| AC-K6 | 送达承诺 | 超过最晚送达的行李不会被分配到该目标航班，并显示原因 |
| AC-K7 | 状态门槛 | 状态为「已装箱」或「已装机」的行李不会出现在可调列表 |
| AC-K8 | 转移问题 | 目标航班调整后超过高风险阈值时，不会被选为目标 |
| AC-K9 | 窗口参数 | 把窗口改为 3 天，候选航班数量随之变化 |
| AC-K10 | 临近起飞 | 起飞前 `alertHours` 内的航班出现在 Q3 区域，显示倒计时、货舱状态与告警等级 |
| AC-K11 | 紧急告警 | 实测累计超预算的航班触发「紧急」，且界面没有任何调度或通知按钮 |
| AC-K12 | 数据来源 | 所有模拟数据显式标注，容量参数带来源编号 |
| AC-K13 | 同步 | 修改一件 Plume 行李重量并保存，≤ 2 秒内余量与风险等级更新 |

## 12. 与现有产品和演示的差异

| 现有能力 | 现状 | 本需求的变化 |
| --- | --- | --- |
| `pages/operations.html` | 单航班 CX257，固定 100 PAX | 扩展为多航班；PAX 取航班座位数或种子数据 |
