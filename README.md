# 泰易送 · 翼隨行 — Plume Light

面向国泰航班旅客的行李准备与递送服务概念原型，为 Cathay Hackathon 项目制作。旅客可以提前申报行李、咨询携带规则、模拟预约上门收取及目的地配送；航司可通过营运看板查看已保存的行李预报，辅助装载规划。

项目使用原生 HTML、CSS 和 JavaScript，采用多页面结构，无需安装前端依赖或执行构建。**根目录的 `index.html` 是唯一主入口。** 本说明存放于 `doc/README.md`，以保持根目录简洁。

> 当前为静态交互演示，没有接入真实订票、付款、会员、物流或大模型服务。页面中的价格、里数、时间、规则和交接事件均为演示数据。

## 快速开始

### 直接打开

1. 下载或接收完整项目文件夹，并先解压压缩包。
2. 在文件夹根目录双击 [index.html](../index.html)。
3. 从首页进入行李准备、AI 出行助手、行程概览或营运看板。

至少保留 `index.html`、`assets/` 和 `pages/`，不要更改它们之间的相对位置。直接打开本地文件时，各浏览器的存储行为可能不同；如遇到跨页面数据无法保留，请使用本地服务器。

### 使用本地服务器

已安装 Python 3 时，在项目根目录运行：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

然后访问 <http://127.0.0.1:8000/>。按 `Ctrl+C` 结束服务器。

请在演示过程中使用同一个浏览器、网址和端口。`localhost`、`127.0.0.1`、不同端口及本地文件属于不同的存储环境，数据不会自动互通。

## 产品功能

| 模块 | 当前实现 |

### 品牌与界面约定

- 繁体版页首使用「**泰易送 · 翼隨行**」，英文 `Plume Light` 紧随其后，以较小字号显示。
- 繁体版页面内容、案例标签、助手及页尾使用简称「**泰易送**」。
- 页首左侧使用国泰标志，右侧使用产品羽毛标志；羽毛也用于首页、行李标签、预订摘要、助手头像、页尾和浏览器标签图标。
- 首页及全部预订步骤的底部展示服务声明：「我們嚴格保密乘客及其行李相關的隱私與資訊。」
- 营运入口及看板页明确标注「僅限國泰員工」。目前这是界面用途说明，尚未实现员工登录或访问权限校验。

### 运输方式

预订的「首末程安排」步骤提供两种选择：

| 选项 | 页面表达 |
| --- | --- |
| 行李随本趟航班 | 与当前 CX257 旅程同行，强调旅客的安心感 |
| 由 Cathay Cargo 调度 | 使用灵活货运调度，强调运输及时性，并说明行李可能分开抵达 |

选择会跨页面保存，并进入结算摘要和订单快照；Cargo 订单的装机说明也会显示 Cathay Cargo。当前两种方式共用演示报价与申请截止逻辑，没有接入实际货运排期、舱位分配、到达承诺或独立运价。

## 推荐演示流程

1. 打开首页，展示 CX257 香港至伦敦希思罗 T3 的行程及目的地 `LSE Student Dormitory 6`；切换语言或大字模式。
2. 点击「行李準備」，确认实际乘机人及联系人；需要时选择家人协助填写。
3. 修改行李重量、尺寸或服务选择，并保存预报。未保存的草稿不会计入营运统计。
4. 在携带规则页询问充电宝等物品，并按提示补充规格，例如 `74 Wh`；查看规则样本及待确认说明。
5. 选择收取地区、取送信息及「随本趟航班」或「Cathay Cargo 调度」。
6. 核对报价，勾选模拟交易确认，选择现金或里数结算，进入行程概览。
7. 展开交接事件演示，依序确认到达机场、部分或全部装机、当地物流接收；服务完成后再查看里数入账。
8. 查看营运看板，观察已保存申报及重量、空间余量变化；最后回到首页查看旅客案例。

页面底部的演示控制台可切换留学生、儿童家庭、超过截止时间、缺少尺寸等场景，并调整演示时钟、航班时间、规则质量或模拟支付失败。

## 演示参数与业务约束

### 默认场景

- 航班：`CX257`，`HKG → LHR T3`。
- 出发：2026 年 11 月 15 日 09:30，香港时间。
- 初始演示时钟：2026 年 11 月 10 日 09:30，香港时间；不会自动随系统日期推进。
- 默认服务行李：4 件，总重 60 kg。
- 默认可用里数：50,000。
- 默认香港取件报价：HKD 1,600；可使用 40,000 里数兑换。现金订单预计赚取 160 里数，服务完成后入账。

上述价格依赖默认行李、地区及尺寸；修改选项后以页面重新计算的演示报价为准。

### 申请截止

| 收取地区文案 | 至少提前申请 | 取件距起飞的最少间隔 |
| --- | --- | --- |
| 香港境内 | 24 小时 | 12 小时 |
| 大湾区其他覆盖地区 | 48 小时 | 24 小时 |
| 出发国境内其他地区 | 120 小时 | 72 小时 |

以当前演示航班的香港出发时刻计算连续小时，恰好等于申请截止时刻仍可申请。取件时间还须符合单独的运输截点。其他未覆盖地区不能新建预约。

「出發國境內其他地區」是当前显示名称；代码沿用地区键 `mainland` 及相应演示参数，尚未实现按任意出发国动态配置覆盖范围。

### 行李、订单与里数

- 全部托运行李预报与购买首末程服务的行李分别统计；服务报价只计算选中的托运行李。
- 同一乘机人及航段按最新有效申报统计。未知重量不当作零；报价需要完整重量与尺寸。
- 演示汇率为 GBP 1 = HKD 10；每 HKD 1 可用 25 里数兑换；每 HKD 10 合资格现金预计赚取 1 里数。这些是代码演示参数，不是现行会员政策。
- 全额里数兑换订单赚取 0 里数。付款失败会释放冻结里数；取消按订单快照处理退款与已入账里数冲销。
- 订单保存确认时的资料和运输方式；后续草稿修改不会改写已有订单。
- 付款成功或航班进度变化不会自动确认行李装机。交接按行李件数确认，可展示部分完成，并防止相同事件重复累计。
- 营运看板的余量是演示预测，未接入真实航班载重或货运销售系统。

## AI 助手与案例

助手由本地意图识别、属性追问和确定性规则样本驱动，没有调用大模型 API 或实时官方检索。覆盖衣物书籍、电池、辅助设备、液体、药品、食品、电子与易碎品，以及截止、价格、里数、交接、家人协助和配送等服务问题。

英国、澳洲及印度提供有限规则样本，法国作为未覆盖目的地示例。缺失、过期、冲突及未覆盖结果会保留待确认提示。咨询其他目的地不会修改当前机票；可回写的行李建议需要用户确认，且不能静默更改已有服务订单。

首页三组案例分别为留学生赴伦敦、儿童赴墨尔本，以及日本研究学者返回札幌。案例人物、结果及引述均为虚构，配图为 AI 生成素材；案例航线不会更改实际演示订单或复用伦敦报价。

轮播在可见时每 8 秒切换；悬停、键盘聚焦、页面隐藏或离开可视区时暂停，也支持按钮、圆点、键盘、触屏及触控板横向手势。

数据保存在浏览器 `localStorage`，不会在不同浏览器或设备间同步：

| 键名 | 用途 |
| --- | --- |

语言列表为 `zh-Hant`、`en`、`fr`、`es`、`ar`；阿拉伯语使用从右向左布局。用户输入的姓名、地址及问题原文不会自动翻译。

## 开发与验证

修改时请遵守以下约定：

1. 保留根目录 `index.html`、`pages/` 和 `assets/` 的层级。页面映射由 `PAGE_FILES` 管理，子页面通过 `ROOT_PREFIX` 返回根目录资源。
2. 各页面的脚本顺序保持 `i18n.js → model.js → app.js`，并正确设置 `<body data-page="...">`。
3. 新增界面文案时，在 `i18n.js` 同时填写五种语言；不要把显示标签直接作为业务状态键。
4. 保留未知值、草稿与提交、申报与服务需求之间的区别。不要用航班起飞、付款或页面动画推导行李状态。
5. 图片随项目本地保存；修改路径后同时检查首页、子页面和分享版。

如已安装 Node.js，可在项目根目录进行语法检查；Node.js 不属于网站运行依赖：

```sh
node --check assets/i18n.js
node --check assets/model.js
node --check assets/app.js
```

修改后应手动检查首页与全部八个功能页、返回首页、五步预订、现金及里数模拟支付、取消订单、运输方式保存、交接状态、语言切换和手机布局。语法检查不能替代浏览器中的交互验证。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 打开首页后空白 | 确认已解压、JavaScript 已启用，且 `assets/` 中三个脚本未遗漏 |
| 子页面或图片无法打开 | 恢复原有目录层级；只复制 `index.html` 无法运行完整网站 |
| 切页后订单、语言或草稿消失 | 使用同一浏览器和同一来源；本地文件模式异常时改用本地服务器 |
| 预约显示超时或取件时间无效 | 检查演示控制台中的当前时间、航班时间、地区截止及取件时段 |
| 无法获取报价 | 确认至少选择一件需要服务的托运行李，并补全其重量与尺寸 |
| 付款后行李仍未装机 | 展开行程页的交接事件演示，按顺序模拟交接确认 |
| 看板与刚输入的重量不同 | 先保存行李预报；看板只读取有效提交，且包含其他演示旅客的基线数据 |
